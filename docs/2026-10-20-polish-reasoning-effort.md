# 작업별 AI 추론 강도 — v1.1.70

## 적용 정책

| 작업 | 요청하는 추론/처리 설정 |
| --- | --- |
| 원문·최소·깔끔하게 일반 받아쓰기 | Low + Fast 요청 |
| 긴 일반 받아쓰기, 사전·교정 규칙 포함 | 길이만으로 승급하지 않고 Low + Fast 요청 |
| 구조화·전문적으로 | Medium + Fast 요청 |
| 번역·선택 편집·초안 작성·장면/사용자 지정 지침 | Medium + Fast 요청 |
| 명시적 질문·검색 | High + Fast 요청 |

선택한 텍스트나 추가 지침이 없는 일반 받아쓰기에 Low를 사용합니다. 표의 장면/사용자 지침처럼 추가 해석이 필요한 경우에는 단순 스타일을 골랐더라도 Medium입니다. 알 수 없는 스타일은 Medium으로 처리합니다. 임의의 키워드로 복잡성을 추측하지 않습니다.

모델은 `gpt-6-luna` 그대로이며 매 요청의 `service_tier="priority"`도 유지합니다. 이는 Fast 요청 설정이지 실제 제공된 서버 처리 등급의 확인 결과는 아닙니다. 전역 Codex 설정·계정·인증 파일·API 계약·프롬프트는 변경하지 않았습니다.

Mac/Home 등 원격 전사 요청의 AI 다듬기도 SB의 동일한 `CodexProvider`를 통과합니다. 스타일·활성 여부의 기존 헤더만 사용하므로 새 필드나 기기 토큰이 필요하지 않습니다. 원격 클라이언트 실행 파일을 아직 업데이트하지 않았더라도 업데이트된 SB 서버를 이용하는 다듬기에는 서버 정책이 적용됩니다.

## 검증

- 기존 동작에서 Low/Medium 계약 검사 3건이 실패하는 것을 먼저 확인하고 분기를 수정했습니다.
- 일반 받아쓰기 3개 스타일, 1,024자 경계 및 8,192자 입력, 사전/교정 규칙, 번역·선택 편집·장면 지침, 질문·검색과 Fast 인자를 검사합니다.
- 기존 구독 인증과 앱 전용 프로필을 사용한 opt-in 모델 검사 두 개를 직접 실행했습니다. 원문 표현, 자가 정정 금액/이름, 부정 표현, 기술 용어, 사전·교정 규칙, 번역·선택 편집·서식 및 1,024자를 넘는 18개 항목의 마지막 정보 보존 등 16개 사례가 통과했습니다. 원문 되돌림이 모델의 누락을 가리지는 않았는지도 검사했습니다.
- 제품에 벤치마크 입력·출력이나 합성 음성을 넣지 않습니다. 기존 opt-in 검사 3개의 기본 비활성 상태는 유지하며, 그중 품질 검사 2개만 명시적으로 실행했습니다. 공유 개발 Codex 프로필 비교 검사는 실행하지 않았습니다.

## 속도에 관한 중요한 한계

같은 입력·프롬프트·모델·Fast 요청 설정으로 이전 추론과 변경 추론을 15쌍 비교했습니다. 각 사례는 한 쌍뿐이며 실행 순서를 섞었습니다.

- 전체 중앙값: **이전 4,295ms / 변경 5,413ms**. 이번 표본은 일반적인 속도 개선을 입증하지 못했습니다.
- 최댓값: 이전 57,700ms / 변경 57,132ms. 어느 한 추론 단계에만 긴 지연이 생긴 것은 아닙니다. 느린 표본을 제외해 속도가 개선된 것으로 계산하지 않았습니다.
- 긴 글 한 사례: High 12,108ms / Low 11,376ms. 이 한 건만으로 긴 녹음 전체의 속도를 보장하지 않습니다.
- 별도 짧은 문장 CLI 진단: Low 4,921ms / Medium 5,641ms, 두 결과 모두 보고된 reasoning output tokens는 0이었습니다. 두 요청에서는 재연결/재시도 경고가 잡히지 않았습니다. 이 진단에서 55초 지연을 재현한 것은 아닙니다.
- 로그인 사전 확인은 10초 제한이 있어 55초대 지연 전체를 그것만으로 설명할 수 없습니다. 나머지 CLI 실행에는 연결·서버 대기·생성이 함께 포함되어 있어 현재 결과로 어느 하나를 원인으로 단정하지 않습니다. 모델이나 TLS/DNS/프록시 설정을 임의로 바꾸지 않았습니다.

따라서 이번 변경은 **승인된 추론 정책 하향**이며, ‘느린 현상 전체 해결’이나 ‘Low는 항상 더 빠름’을 의미하지 않습니다. 실제 마이크·커서 입력 및 녹음 종료부터 입력 완료까지의 시간은 별도 실사용 검증입니다. 설치/빌드 결과는 인수 기록과 QA 영수증에 구분해 남깁니다.

검증 원본: 저장소 밖 `qa/polish-effort-20261020/`. 첫 비교의 PowerShell 콘솔 재인코딩이 한글 로그 표시에 영향을 주었으나, Rust 내부 원문 보존 판정과 ASCII 시간 필드는 영향을 받지 않았습니다. 후속 실행기에는 UTF-8 출력을 명시했습니다.

## 빌드·실제 반영

- Windows 전체 검증: 프런트엔드 477개, Node 검증기 7개, Rust 단위 715개·통합 9개 통과. 서식·타입·린트·Clippy·빌드·npm audit(취약점 0개) 통과. 최종 production 실행 파일의 격리 UIA helper 검사 3개도 통과했습니다.
- Mac: 프런트엔드 477개, Rust 단위 708개·통합 1개, 서식·타입·린트·Clippy·production 앱 빌드·엄격한 서명 검증 통과. 두 플랫폼 모두 기존 opt-in 검사 3개는 기본 실행에서 제외되며, 앞의 실제 모델 품질 검사 2개는 별도로 실행했습니다.
- SB·Mac에 v1.1.70을 설치했습니다. 기존 설정·인증·단축키·기록·복구 음성을 보존하고, SB의 내장 프런트엔드 요청과 초기/중복 자동 실행의 백그라운드 동작, Mac의 설치 버전·해시·서명·실행 프로세스를 확인했습니다. 전역 Codex 설정은 바꾸지 않았습니다.
- Home은 처음 보류했다가 사용자가 전원을 켜고 설치를 요청한 뒤 동일한 v1.1.70 실행 파일을 설치했습니다. 기존 Insert 단축키·설정·인증·79개 기록·복구 음성을 보존하고, 실제 Session 1 프로세스·내장 프런트엔드·초기/중복 백그라운드 실행을 확인했습니다. 설치와 검증에 쓴 임시 작업 등록 두 개는 삭제했습니다.
- 설치된 SB 서버에 Mac의 기존 HTTPS·인증 설정으로 같은 짧은 합성 음성을 5번 요청했습니다. 원문·최소·깔끔하게는 실제 로그에서 Low, 구조화·전문적으로는 Medium, 모두 `service_tier="priority"` 요청으로 확인했습니다. 정상 응답, 원문 보존과 핵심 내용 유지가 통과했고 Mac 설정은 그대로였습니다. 이 응답들이 AI 실패에 따른 원문 되돌림만으로 통과한 것으로 보지 않도록 서버의 정상 cleanup 완료 로그도 대조했습니다.
- 위 5건의 종단 요청 시간은 각각 5,061 / 6,322 / 3,926 / 3,838 / 6,965ms입니다. STT·네트워크·AI가 모두 포함되며, 이전 버전과의 대조 측정이 아니므로 속도 개선의 근거로 사용하지 않습니다.
- 실제 사람이 마이크로 말한 뒤 대상 커서에 입력되는 과정과 선택 편집은 이번 변경 후 새로 검증하지 않았습니다. Mac의 기존 `selected_text_enabled=false`도 변경하지 않았습니다. Android·CI·의존성·서버 인증 계약은 변경하지 않았고, 이번 변경을 커밋·푸시·릴리스하지 않았습니다.

## Home·Fold7 후속 적용

- Home의 기존 사용자 자격 증명으로 HTTPS 통신 검사 11개를 통과했습니다. 인증 누락/오류 거부, 잘못된 음성/과도한 힌트 거부, 바로입력·일반 전사, 다섯 다듬기 스타일 모두 정상입니다. 서버 로그에서 해당 다섯 요청이 Low/Low/Low/Medium/Medium 및 priority 요청으로 완료됨을 확인했습니다. Home 설정 파일의 해시도 설치 전후 동일합니다. 실제 마이크·커서 입력은 별도입니다.
- 모바일은 `VoiceAccessibilityService`가 현재 모드·다듬기 활성 여부를 `TranscriptionRequest`에 넘기고, 기존 `x-ultra-stt-polish-style`/`x-ultra-stt-polish-enabled` 헤더로 같은 SB 다듬기 경로를 사용합니다. 따라서 새 서버 정책은 APK 변경 없이 적용됩니다. 불필요하게 Android 버전을 올리거나 기존 앱을 재설치하지 않았습니다.
- Fold7은 최초 USB 연결 누락과 일시적인 디버깅 인증 대기로 검증이 지연됐으나, 이후 Home USB 연결이 인식됐습니다. 실제 SM-F966N의 기존 `.10` APK 해시가 검증된 산출물과 일치했고, 현재 최소 모드·AI 다듬기 활성화·SB HTTPS 주소·암호화된 인증 정보 존재·접근성 활성 상태를 확인했습니다. 인증 값은 내보내지 않았습니다.
- 설치된 기존 앱을 열어 자체 연결 검사에서 `✓ PC 서버 연결·인증 확인됨 · 토큰 입력 불필요`를 실제 UI에서 확인했습니다. 앱 재설치·강제 종료·권한/DNS/VPN 변경 없이 설정 파일의 값과 바이트도 모두 보존됐습니다. 검사기의 최초 성공 문구 기대값은 앱 리소스의 체크 표시·접미사를 빠뜨려 실패했으며, 실제 리소스의 전체 문구와 비교하도록 QA만 수정해 통과했습니다. 제품의 네트워크 오류를 고쳤다는 의미가 아닙니다.
- Fold7에서 현재 최소 모드로 사용하는 다듬기는 SB의 Low + Fast 요청 정책을 적용받습니다. 모바일에서 새 음성을 녹음해 커서까지 입력하는 과정, 다섯 모드 각각의 모바일 음성 요청, 모바일 속도 비교를 새로 실행한 것은 아닙니다. 이를 앞서 통과한 Home/Mac의 합성 음성 검사와 구분합니다.
