# 데스크톱 안정성 업데이트 — 2026-10-11

## 적용 내용

- 녹음 길이에 맞춰 STT·업로드·완료 대기 시간을 계산한다. AI 다듬기에 실패하더라도 성공한 전사 원문은 유지한다.
- 일반 받아쓰기·번역 녹음은 장치의 `recording-recovery` 폴더에 임시 WAV로 기록한다. 입력 실패 시 앱 종료 뒤에도 복구 화면에서 원본 재전사·원문 복사·명시 삭제가 가능하다. 정상 입력 또는 명시 취소는 해당 원본만 정리한다.
- 최대 20개/512MiB이며 저장소가 가득 차면 기존 실패 녹음을 지우지 않고 새 녹음을 막는다. 로컬 파일은 암호화되지 않는다. 별도 Ask 녹음과 Android는 이번 범위가 아니다.
- Windows 기본 입력란 식별을 일관되게 유지하고, 녹음창 자신이 포커스를 가진 경우에만 원래 대상 창으로 돌아가 다시 검증한다. 다른 입력란으로 바뀐 경우 자동 입력 차단은 유지한다.
- 로그인 자동 실행은 `--autostart`로 창을 열지 않고 시작한다. 이미 실행 중인 앱에 같은 인자로 다시 실행해도 메인 창을 열지 않는다. 수동 실행과 트레이 메뉴는 그대로 유지한다.
- Mac 1.1.63 별도 소스에 있던 AX 선택 조회 helper, 기존 Codex 실행 경로, 원격 선택 명령·번역 처리도 공통 소스에 통합했다. 기존 Windows UIA/Ctrl+Insert 안전 경로는 유지한다.

Windows 대화형 사용자 세션에서 전체 `npm run verify`가 통과했다. 프런트엔드 443개, 검증 실행기 7개, Rust 676개 및 통합 9개가 통과했고 기존 opt-in 3개는 유지했다. npm 감사는 취약점 0이었다. 앞서 Session 0에서 실패한 최상단 창 검사도 실제 사용자 세션에서는 수정·제외 없이 통과했다.

Mac에서는 프런트엔드 443개, Rust 669개 및 해당 플랫폼 통합 1개가 통과했다. Rust fmt/Clippy도 통과했으며 기존 opt-in 3개는 유지했다. Windows·Mac 모두 기존 번들 크기/동적 import 안내는 남아 있다.

10분 PCM 보존과 실패/재시작 복구는 자동화 검사이며, 사람이 실제 10분간 말한 결과의 정확도나 모든 편집기 자동 입력을 보증하는 검사는 아니다. 이전 버전이 원본을 저장하지 않은 과거 실패 음성은 복구할 수 없다.

## Windows 화면 로딩 장애 정정 — 20:19

초기 설치 파일 `BD5E55F1…`은 잘못된 `cargo build --release` 명령으로 만들어졌다. Tauri의 `custom-protocol` 기능이 빠져 실행 파일은 존재해도 화면이 내장 파일 대신 `localhost:1420` 개발 서버를 요청했다. 프로세스·백그라운드 창·UIA helper 검사만으로 화면 성공을 판단한 것이 불충분했다. 이 파일은 정상 설치본으로 간주하지 않는다.

Home은 기존 1.1.62로 먼저 복원한 뒤 `npm run tauri -- build --no-bundle -- --locked`로 만든 최종 1.1.64를 설치했다. Home PID 26160, SB PID 47356에서 실제 프런트엔드의 `get_config` 호출과 `production_assets=true` 로그를 확인했다. 두 장치 모두 설정·인증·전체 기록(Home 43개/SB 22개)과 기존 실패 음성 파일의 체크섬이 유지됐으며, 초기/중복 자동 실행 시 창이 숨겨지는 검사도 통과했다. 이 변경으로 Mac 앱을 다시 교체하지 않았다.
