# 긴 녹음·단독 단축키·실행창 보완 — 1.1.66

## 긴 녹음에서 앞부분만 남는 문제

원인 후보를 녹음 수집, STT 원문, AI 다듬기, 실제 입력으로 구분했다. 성공으로 처리돼 정리된 과거 원본은 남아 있지 않아, 사용자가 겪은 특정 녹음의 원인을 하나로 단정하지 않는다. 다만 다음 **실제 데이터 유실 경로**를 코드와 재현 검사로 확인했다.

- 기존 오디오 콜백은 전송 큐의 `try_send`가 실패해도 이미 꺼낸 샘플을 버렸다. 2분 PCM·막힌 수신 큐 검사에서 1,920,000개 샘플 중 첫 320개만 남는 실패를 재현했다. 수정본은 큐가 빌 때까지 샘플을 보관하고, 종료 시 남은 마지막 조각도 수신 측에 전달한다. 실시간 콜백을 블로킹하지 않으며 종료 후 전용 캡처 스레드에서만 잔여 데이터를 전달한다.
- 드라이버 오류는 로그만 남기고 녹음 화면이 계속 진행될 수 있었다. 이제 런타임 캡처 오류와 수신 채널 종료를 감지해 녹음을 중단하고, 부분 결과를 정상 완료로 입력하지 않는다. 기존 원본 복구 파일은 보존한다.
- AI가 긴 받아쓰기의 짧은 도입부만 그대로 반환하는 경우 원문으로 되돌린다. 문장부호·공백을 제외한 긴 원문의 3분의 1 미만이면서 도입부와 일치하는 경우만 대상으로 하고, 온전한 간결화와 선택 텍스트 편집은 구분한다. 이 검사는 의미 누락 전반을 판정하는 AI 정확도 보증이 아니다.
- 앞서 로컬에 있던 바로입력 마지막 요청 재시도 수정도 포함한다. 1·2회 일시 실패에서는 같은 음성을 재시도하고, 3회 반복 실패는 오류로 처리한다.

반복 문장으로 만든 132.445초 시험은 원문 끝까지 인식했다. 다듬기 시 반복 내용이 합쳐지는 것은 누락과 구별해야 하므로, **서로 다른 물류 계획 내용으로 만든 124.320초 합성 음성**도 따로 시험했다. 원문 802자, 최소 다듬기 814자였고 초반·중간·마지막 문장이 모두 있었다. 이 수치는 통제된 시험 파일 결과이며 실제 마이크 수집·모든 문장의 정확도를 보증하지 않는다. 모델·인증·다듬기 프롬프트는 변경하지 않았다.

## 단축키

- 기존 단독 문자·숫자·기호 키 외에 Windows·macOS의 Shift/Ctrl/Alt/Meta 및 좌우 수정키 단독 탭을 지원한다. 단독 수정키는 다른 키와 조합하지 않고 **뗄 때 토글**하며 Ctrl+C 같은 조합과 키 반복을 제외한다.
- CapsLock, NumLock, ScrollLock, PrintScreen, Pause, F13–F24의 저장 정규화와 파서를 확장했다. 실제 등록은 각 OS가 제공하는 키 매핑과 충돌 여부에 따르며 실패를 숨기지 않는다.
- Enter/Escape 자체를 시작 단축키로 쓰더라도 녹음 중에는 Enter 종료·Escape 취소로 라우팅한다. 사용자 소유의 영구 등록을 임시 녹음 키 등록과 혼동해 해제하지 않는다.
- 기존 Mac Fn/조합 키, Windows RightAlt/조합 키를 보존했다. **Windows Fn, 일부 IME 키, OS 예약 키나 다른 프로그램이 가로채는 키까지 전부 지원한다고 보장하지 않는다.** 단독 문자·Space 등을 지정하면 평소 타이핑을 방해할 수 있다.

## 실행창

매 새 녹음은 **메인 모니터 작업영역 중앙**에서 시작한다. 녹음 도중 드래그한 위치는 유지하고 다음 녹음에는 기본 중앙으로 돌아온다. 준비·녹음·처리·완료·실패 화면은 공통 `420×64` shell을 사용하고 기본 native webview는 투명 여백을 포함해 `444×88`이다. 메뉴·상세 확장은 별도 공간을 유지한다. 본문 글자를 14px로 키웠고 실패 화면도 같은 외곽 크기를 사용한다.

실제 브라우저에 React 캡슐을 합성 상태로 렌더링해 녹색·빨간 화면의 동일 크기와 빨간 화면 우측 잔여 배경이 없음을 확인했다. 녹음이나 개인 데이터는 쓰지 않았다. 이 미리보기는 실제 다중 모니터·다중 DPI 실기기 동작과 구분한다. Windows 설치 앱의 설정 화면과 새 단독키 안내도 Computer Use로 확인했다.
