# 결과 복구와 입력 대상 보호

## 구현 범위

- 데스크톱 좌측 메뉴에 **입력 복구**를 추가했다. 대기 수, 결과 전문, 대상 앱, 발생 시각, 복구 사유를 표시하고 사용자가 복사하거나 지울 수 있다.
- 실패 결과는 기록 저장 설정과 별개의 프로세스 메모리에 최근 20개를 보관한다. 자동 재입력하지 않으며, 복사해도 남는다. 앱을 종료하면 사라진다.
- 캡슐은 실패 후 복구 알림과 복사 버튼을 제공한다. 새 녹음이 시작되면 알림만 접고 복구 목록은 유지한다.
- 출력 실패, 대상 변경, 부분 입력, 의도하지 않은 클립보드 fallback을 수집한다. 완성된 응답이 있으면 전문을 보관하고, 스트리밍 도중 모델 자체가 실패하면 확보한 부분만 보관한다. 명시적인 클립보드 복사 모드의 정상 결과는 실패로 분류하지 않는다.
- Android는 마지막 실패 결과 한 개를 프로세스 메모리에 보관하며 녹음 화면과 앱 설정 화면에서 복사·삭제한다. 전송 중 입력 대상이 바뀌면 자동 입력을 멈추고 도착한 결과를 보관한다. 명시적 취소나 새 세션 뒤 도착한 오래된 응답은 폐기한다.

## 입력 대상 확인

- Windows: PID/앱 이름뿐 아니라 foreground HWND, focus HWND, UI Automation runtime ID를 확인한다. UIA 조회가 불가능할 때는 실제 `Edit`/`RichEdit` native control만 HWND 대체 확인을 허용한다. 나머지는 자동 입력하지 않는다.
- macOS: 접근성의 창·입력 요소를 보존한 참조와 `CFEqual`로 비교한다. 조회 실패나 보존 목록(128개)에서 빠진 대상은 불일치로 처리한다. Ask 복원도 원래 창을 지정한다.
- 스트리밍 chunk와 최종 잔여 문장 삽입 전에도 현재 대상을 재확인한다. Linux의 기존 PID/앱 기반 지원 범위는 유지했다.
- 모델/STT 경로와 프롬프트는 바꾸지 않았다. 다만 대상 확인 비용은 추가된다. Windows UIA 조회 응답 대기는 호출당 최대 150ms이며, 일반 응답 시간과 실제 음성 전체 지연은 측정하지 않았다. 스트리밍 삽입을 켜면 chunk마다 확인한다.

## 검증

- 프런트 전체 Vitest: 45개 파일, 423개 테스트 통과. 최종 번역 키/부분 입력 경고 보완 후 관련 2개 파일의 4개 테스트도 통과했다.
- 프런트 TypeScript/Vite 빌드 및 ESLint 통과.
- 번역 키 일치 검사를 그대로 유지했다. 새 문구는 한국어/영어를 제공하고, 나머지 8개 언어에는 영어 문구를 명시했다.
- Windows Rust: `cargo test --locked --offline --lib --manifest-path src-tauri/Cargo.toml -- --quiet` — 638개 통과, 기존 3개 ignored. CMake PATH와 기존 offline Cargo cache를 사용했다.
- Android: `VoiceTests` 85개, `assembleDebug`, `lintDebug`, APK 서명 검증 통과.
- Playwright 브라우저: 실제 UI 컴포넌트와 샘플 데이터를 사용해 900×700/720×480에서 복구 목록, 복사 성공, 삭제 후 건수, 빈 상태를 확인했다. 이 화면 검사는 Tauri IPC를 모의 처리했다.
- 기존 원본 worktree의 미추적 조사 문서, 실행 중인 앱과 서버를 보존했다. installer 스크립트는 실행 중 앱을 종료하므로 사용하지 않았다.

macOS 빌드·실기, Android 설치·실기, 새 데스크톱 바이너리로 실제 음성 입력은 이번 검증에 포함하지 않았다. 운영 앱 설치·교체 및 원격 push/배포도 수행하지 않았다.
