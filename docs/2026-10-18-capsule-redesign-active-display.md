# 실행창 디자인 강화와 활성 창 모니터 배치 — 1.1.67

## 바뀐 경험

- 단색 녹색 바를 짙은 에메랄드 표면, 내부 하이라이트, 명확한 상태·시간·동작의 2행 구조로 바꿨습니다.
- 원본 Ultra STT 브랜드 아이콘은 24px에서 52px로 확대했습니다. 녹음·처리·완료·오류·복구 상태가 같은 520×96px 외형을 사용합니다. 외부 사각 배경이나 바깥 그림자는 추가하지 않습니다.
- 음성 파형은 28개 막대, 높이 32px입니다. 실제 마이크 RMS를 시각적으로만 보정해 작은 목소리도 읽기 쉽게 표시합니다. 녹음 데이터나 STT 입력 음량은 바꾸지 않습니다. 무음에 말하는 듯한 가짜 파형을 만들지 않습니다.
- 녹음 시작 전 활성 애플리케이션 창이 있는 모니터를 저장하고 그 모니터 작업 영역 가운데에 표시합니다. 녹음 중 드래그 위치는 유지하며 다음 녹음에서 다시 활성 창 기준으로 배치합니다.
- 모드·바로입력 전환, 취소, 번역 언어, 입력 복구를 유지했습니다. 동작 줄이기 설정에서는 흔들리는 애니메이션 없이 실제 음량 변화만 표시합니다.
- 등장·퇴장은 창을 늘리거나 찌그러뜨리는 layout 애니메이션 대신 180ms 등장 / 120ms 퇴장으로 통일했습니다. 실제 창이 표시된 뒤 등장하고, 퇴장이 끝난 뒤에만 창을 숨깁니다. 종료 순간 작은 대기 아이콘으로 먼저 바뀌거나 새 녹음을 이전 종료 콜백이 숨기지 않도록 순서를 보호합니다. 처리 단계끼리는 blur 없이 짧게 교차 전환합니다.

## 모니터 선택이 달라진 이유

macOS의 시스템 primary display와 사용자가 작업하는 외장 모니터는 같지 않을 수 있습니다. 이전 구현은 primary를 우선했으므로 MacBook 화면에 뜰 수 있었습니다. 새 구현은 녹음창이 나타나기 **전**에 대상 화면을 고정합니다. 녹음창 자체나 마우스 위치를 입력 대상으로 오인하지 않습니다.

- macOS: 기존 접근성 권한이 있을 때 실제 `AXFocusedWindow`의 위치·크기를 먼저 조회합니다. 조회당 30ms 제한으로 응답 없는 앱의 대기를 제한하고, 실패하면 현재 활성 앱 PID의 일반 창 경계(CoreGraphics, layer 0)로 복귀합니다. 여러 화면에 걸친 창은 겹친 면적이 가장 큰 디스플레이를 고릅니다. 창 제목·내용·화면 이미지는 읽거나 저장하지 않습니다. 새 권한 요청이나 의존성을 추가하지 않습니다.
- Windows: 녹음 시작 시 foreground window의 화면 좌표를 사용합니다. UI Automation이나 클립보드·키 입력을 추가하지 않습니다.
- 화면을 찾지 못했거나 연결이 해제되면 현재 사용 가능한 primary/current 화면으로 안전하게 복귀합니다. Linux는 기존 fallback 배치를 유지합니다.
- macOS Retina/외장 화면처럼 배율이 다를 때는 대상 화면의 논리 좌표로 이동해 기존 녹음창 화면 배율의 영향을 피합니다.
- 화면 연결 해제 검사도 공통 논리 좌표계로 비교합니다. 모드 메뉴를 연 채 이동한 경우에도 닫을 때 드래그한 거리와 화면 배율을 반영합니다. 공용 카드 스타일 때문에 메뉴가 실행창 위에 겹치던 문제를 분리하고, 메뉴가 잘리지 않도록 확장 영역을 504px로 확보했습니다.

원리 확인: [Apple 창 메타데이터 API](https://developer.apple.com/documentation/coregraphics/cgwindowlistcopywindowinfo(_:_:)), [화면 좌표 원점](https://developer.apple.com/documentation/coregraphics/kcgwindowbounds). 실제 좌표 변환은 프로젝트의 고정된 Tauri 2.11.2 / Tao 0.35.3 구현과 대조했습니다.

## 검증과 적용 기록

현재 작업의 QA 로그는 저장소 밖 `qa/capsule-20261018`에 있습니다. 원본 녹음·인증·기록과 기존 미커밋 변경은 보존합니다. 설치·실사용 결과는 HANDOFF의 최신 항목을 기준으로 확인해야 합니다. 브라우저의 합성 상태 미리보기나 빌드 통과만으로 실제 음성 입력·다중 모니터 검증이 끝났다고 간주하지 않습니다.

- Windows: 실제 Session 1에서 전체 `npm run verify` 통과. 프런트엔드 473개, 검증 스크립트 7개, Rust 713개 및 통합 9개 통과, 기존 ignored 3개 유지, npm audit 0건. 최종 release 실행 파일의 UIA helper 통합 검사 3개도 통과했습니다.
- macOS: 프런트엔드 473개, Rust 706개 및 플랫폼 통합 1개, fmt/Clippy/프로덕션 빌드/strict signature 통과. 실제 Mac에서 앱과 같은 네이티브 조회 코드를 별도 QA 실행 파일로 실행해 기존 접근성 권한으로 외장 화면의 중심 `(3400, 900)`을 65ms에 찾았습니다. 시스템 기본 화면은 MacBook이고 작업 창은 외장 화면에 있었습니다.
- 실제 브라우저에서 원본 아이콘·파형·오류 외형을 확인했습니다. 퇴장 시작에 큰 외형이 유지되고 작은 대기 아이콘으로 먼저 변하지 않으며, 퇴장 후 사라지고 새 등장은 native show를 기다리는 것을 확인했습니다. 모드 메뉴는 본체 아래 4px 간격, 다섯 모드가 확장 영역 안에 표시됩니다.
- SB와 Mac에 1.1.67 설치 완료. 설정·인증·기존 기록·복구 음성은 보존했고 SB의 초기/중복 자동 시작 백그라운드 동작을 확인했습니다. 설치 후 SB 일반 전사/바로입력, Mac→SB HTTPS 전사(AI 켜기/끄기)가 모두 통과했습니다. Home은 SSH 연결이 되지 않아 교체하지 않았습니다. 사람이 실제 녹음을 시작했을 때의 외장 모니터 위치·체감 애니메이션·커서 입력은 사용자 확인 전입니다.
