# 밝은 실행창과 움직이지 않는 모드 선택 — 1.1.68

## 요청 반영

- **일반 STT:** 밝은 녹색 표면과 진한 녹색 글자·음성 파형.
- **바로입력:** 별도의 밝은 파란색 표면, `바로입력` 상태와 큰 `STT` 복귀 버튼.
- **오류:** 배경 전체를 선명한 빨간색으로 표시하고 흰 오류 문구를 사용합니다.
- **클릭 영역:** LIVE/STT 전환 84×44, 취소 44×44, 다듬기 모드 136×44px. 펼쳐진 모드 선택도 각 약 83×60px입니다.
- **브랜드:** 기존 원본을 새로 그리지 않고 64px 원형 배경·원형 마스크로 표시합니다. 검은 네모가 드러나지 않도록 이미지 부분에만 블렌딩하며, 본문 글자에는 적용하지 않습니다.

## 모드를 누르면 창이 이동했던 이유

기존 구현은 모드 메뉴를 열 때 네이티브 창 높이를 늘리고 위쪽으로 위치를 보정했습니다. 메뉴를 닫을 때는 다시 원래 위치를 계산했습니다. 메뉴 자체를 실행창 밖으로 펼치던 구조가 이동의 원인이었습니다.

새 구현은 **같은 실행창 안에 다섯 모드를 가로로 표시**합니다. 일반 녹음창은 560×112px이고, 투명 여백을 포함한 네이티브 창은 584×136px입니다. 모드를 열고 닫아도 크기와 위치가 동일하며, 이 경로에서는 native `setSize`/`setPosition`을 호출하지 않습니다. 모드를 바꿔도 녹음은 종료되지 않습니다. 현재 선택 표시, 저장 실패 알림·재시도, Esc로 메뉴만 닫는 동작을 유지합니다.

앞서 수정한 활성 입력창 모니터 선택, 드래그, 180ms 등장·120ms 퇴장, 동작 줄이기 설정은 유지합니다. 모델·STT·녹음 데이터·인증 설정은 바꾸지 않습니다.

## 확인 범위

실제 React UI를 브라우저에 렌더링하고 녹색·파란색·빨간색, 원형 브랜드, 클릭 영역, 본체 안 다섯 선택 버튼을 확인했습니다. 이 미리보기는 합성 상태와 native IPC mock을 사용하며 실제 녹음 검증과는 구분합니다.

회귀 테스트는 수정 전에 메뉴 열기 시 504px 높이 변경을 검출해 실패했고, 수정 후 메뉴 열기·닫기에서 크기·위치 변경 호출이 0회인지 확인합니다. 원래 저장 상태와 선택 실패도 검증합니다. QA 로그와 설치 결과는 저장소 밖 `qa/capsule-bright-20261018` 및 HANDOFF 최신 항목에 기록합니다. 현재 작업은 새 의존성·권한·CI·원격 저장소를 변경하지 않습니다.

- Windows: 실제 Session 1에서 전체 검증 통과. 프런트엔드 475개, 검증 스크립트 7개, Rust 713개와 통합 9개, 최종 release 실행 파일 helper 3개 통과. 기존 ignored 3개는 그대로이며 npm audit 0건입니다.
- macOS: 프런트엔드 475개, Rust 706개와 플랫폼 통합 1개, fmt/Clippy/프로덕션 빌드/strict signature 통과. 두 기기에 올린 소스 47개 파일의 해시가 동일합니다.
- SB·Home·Mac에 1.1.68 설치 완료. 기존 설정·인증·기록·복구 음성을 보존했습니다. Mac 기록 83개와 Home 기록 75개를 그대로 유지했고 SB·Home의 초기·중복 자동 시작 숨김 동작도 확인했습니다. Home은 연결 복구 후 같은 검증된 Windows 실행 파일로 업데이트했습니다.
- 설치된 앱에서 사람이 직접 녹음·전사·입력과 버튼 체감을 확인하는 것은 자동검사·브라우저 합성 상태 확인과 별개입니다. 이번 변경은 모델이나 음성 입력 처리 경로를 변경하지 않습니다.
- 설치 후 SB 일반 전사·바로입력, Mac→SB HTTPS 전사(AI 켜기/끄기)도 합성 음성으로 통과했습니다. 실제 사람의 마이크·커서 입력 검증으로 대신 해석하지 않습니다.
- Home에서도 인증 거부·잘못된 입력 처리·바로입력·일반 전사·AI 다듬기 등 7개 통신 검사를 통과했습니다. 기존 `Insert` 단축키와 서버 인증은 그대로입니다.
