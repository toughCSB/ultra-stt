# 녹음창 최상단 표시 수정과 모바일 사용 화면

2026-10-03 · 기존 설정·기록·인증을 보존하는 데스크톱 후속 수정.

## 무슨 문제였나요?

Home에서 단축키가 고장 난 것으로 보였지만, 사용자는 **녹음창이 다른 창 뒤에 가려져 보이지 않았던 것**으로 증상을 정정했다. 절전 복귀와 겹쳤다는 사실만으로 절전이 원인이라고 단정하지 않는다.

기존 설정에도 `alwaysOnTop: true`가 있었다. 하지만 표시할 때 `show()`만 호출했고, 이후 다른 최상단 창이 앞에 오는 경우를 복구하지 않았다. 사용 중인 Windows 창 라이브러리는 이미 true인 최상단 플래그를 다시 true로 설정하면 실제 창 순서를 바꾸지 않을 수 있다. 설정값만 다시 넣는 대신 실제 운영체제 창 순서를 갱신하도록 수정했다.

## 어떻게 바뀌었나요?

- 창을 보여 줄 때와 녹음·처리 등 작업이 진행 중일 때 1초 간격으로 표시 순서를 복구한다. 대기 상태에서는 주기 작업을 중단한다.
- Windows는 `SetWindowPos(HWND_TOPMOST)`를 사용하되 `SWP_NOACTIVATE`로 기존 입력창의 포커스를 유지한다.
- Mac은 `CGWindowLevelForKey(9)`로 status 수준을 적용하고 `orderFrontRegardless`로 올린다. 키보드 입력 포커스를 가져오지 않는다.
- 숨긴 창은 다시 열지 않는다. 취소·자동 숨김 직후 늦게 도착한 요청도 실제 창의 표시 여부를 검사한다.
- 녹음창에서만 명령을 사용할 수 있다. 새 프로그램·상주 서비스·권한·의존성을 추가하지 않았다.

여기서 **최상단은 일반 데스크톱 앱 창 기준**이다. UAC, 잠금 화면, 운영체제 보안 화면, 일부 독점 전체 화면을 덮겠다는 의미가 아니다. 다른 최상단 앱이 동시에 창 순서를 계속 바꾸는 경우 일시적으로 가려질 수 있다.

## 모바일 화면은 무엇을 보여 주나요?

실제 갤럭시의 설치된 Android .9와 ChatGPT 새 입력창에서 촬영했다. Android 코드나 설치 버전을 바꾼 작업은 아니다.

1. [대기 마이크](images/android-idle-mic.png): 기존 삼성 키보드 위의 작은 음성 버튼.
2. [반원 메뉴](images/android-radial-modes.png): 길게 누르면 다섯 모드의 색상과 아이콘 표시.
3. [드래그 선택](images/android-mode-drag.png): 손가락을 구조화 아이콘으로 옮겼을 때 흰 선택 테두리. 손을 떼면 적용.
4. [녹음창](images/android-recording-chatgpt.png): 키보드를 숨기고 로고·현재 모드·타이머·종료·취소 표시.
5. [녹음 중 모드 변경](images/android-recording-mode-picker.png): 모드 이름을 눌러 펼친 다섯 선택지.

드래그는 **모드 선택**이며 마이크 위치 이동 기능이 아니다. 영어 예시 문구는 직접 입력한 미전송 초안이며 전사 결과가 아니다. 촬영 후 초안을 지우고 녹음을 취소했으며 음성이나 대화 메시지를 전송하지 않았다. 원래 최소 모드로 복원했다. 개인 대화·설정의 인증 정보는 게시하지 않는다.

## 배포 파일과 소스 구분
