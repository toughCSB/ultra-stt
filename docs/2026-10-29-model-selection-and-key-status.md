# v1.1.73 — 엔진·모델 선택과 API 키 저장 상태

2026-10-29 작업 기록이다. 소스·검사·설치와 실제 마이크 사용 검증을 구분한다. 이전 문서의 미설치 표시는 당시 상태이며, 최신 설치 현황은 이 문서를 기준으로 한다. 설치 후 사용자가 소스·문서의 커밋·푸시를 승인했으며, 별도 릴리스 파일·태그 변경은 포함하지 않는다.

## 설정 방법

1. **엔진 선택**의 큰 카드 두 개 중 하나를 선택한다. 기존 연결은 현재 Whisper/개인 서버 설정을 유지하고, OpenAI는 `gpt-transcribe`로 직접 전사한다.
2. OpenAI를 사용하려면 API 키를 입력하고 **저장**한다. 성공하면 저장 완료와 가려진 키 상태가 표시되고 입력칸은 닫힌다. **수정**을 눌러야 빈 입력칸이 다시 열린다. 취소하거나 저장에 실패하면 기존 키를 유지한다.
3. 데스크톱의 엔진·모델 변경은 별도의 설정 **저장**으로 적용한다. 카드의 선택 초안과 실제 저장된 엔진을 구분한다. 키 저장만으로 엔진까지 바뀌지는 않는다. 모바일의 엔진 카드 선택은 다음 녹음에 적용된다.
4. **연결 테스트**로 현재 선택을 확인한다. 저장 완료는 보관 성공이지, 계정 권한·잔액·연결 성공을 뜻하지 않는다. 선택이나 키를 바꾸면 이전 테스트 결과를 지운다.

키는 기존 OS 자격 증명 저장소 또는 AndroidKeyStore 기반 저장을 사용한다. 기존 키를 화면으로 읽어 오지 않으며, 소스·로그·설치 파일에 포함하지 않는다.

## 데스크톱 모델과 실제 처리 위치

| 선택 모델           | 기존 전사 엔진                | OpenAI 전사 엔진              |
| ------------------- | ----------------------------- | ----------------------------- |
| `gpt-6.1-sol`       | 해당 컴퓨터의 Codex CLI       | OpenAI Responses API          |
| `gpt-6.1-terra`     | 해당 컴퓨터의 Codex CLI       | OpenAI Responses API          |
| `gpt-6-luna`        | 해당 컴퓨터의 Codex CLI       | OpenAI Responses API          |
| `claude-haiku-5-5`  | 해당 컴퓨터의 Claude Code CLI | 해당 컴퓨터의 Claude Code CLI |
| `claude-sonnet-5-5` | 해당 컴퓨터의 Claude Code CLI | 해당 컴퓨터의 Claude Code CLI |
| `grok-4.7`          | 지원 대기·선택 비활성화       | 지원 대기·선택 비활성화       |

데스크톱이 SB에서 Whisper 전사를 받더라도 서버에는 다듬기를 요청하지 않는다. 원문을 받은 뒤 **해당 컴퓨터에서 선택한 CLI/API**로 한 번만 다듬는다. 따라서 Home·Mac은 선택한 로컬 CLI에 로그인되어 있어야 한다. OpenAI 전사와 OpenAI 다듬기를 함께 선택하면 SB 없이 처리한다. Claude를 선택하면 별도 Anthropic API 키가 아니라 해당 PC의 Claude Code 구독 인증을 사용한다.

모바일에는 Claude·Grok 공급자를 추가하지 않았다. OpenAI 경로는 기존처럼 `gpt-transcribe`와 `gpt-6-luna`를 API 키 하나로 직접 사용한다. 모바일의 기존 경로는 SB의 전사·Codex 다듬기를 유지한다. 사용자 선택 엔진을 업데이트 과정에서 강제로 바꾸지 않는다.

### Grok을 활성화하지 않은 이유

설치된 Grok CLI `1.0.70`의 모델 목록에서 요청한 `grok-4.7`을 확인하지 못했고, 전역 hooks/plugins/MCP를 요청 한 번에 안전하게 배제하는 경로도 검증되지 않았다. API에 모델이 있다는 사실만으로 CLI 지원을 가정하지 않는다. 모델을 몰래 대체하거나 API 키 경로로 우회하지 않으며, 백엔드도 텍스트 전송 전에 명시적으로 실패한다. 별도 `GROK_HOME`과 로그인 도입은 이번에 진행하지 않았다.

### CLI 실행의 범위

CLI는 도구 없는 텍스트 처리로 제한하며, 앱 전용 작업 디렉터리·시간 제한·자식 프로세스 정리를 사용한다. Claude의 실제 요청 모델, 완료 상태, 도구/권한 요청 여부를 검사한다. Codex는 기존 SB 전용 프로필을 유지하고, 별도 루트가 없는 컴퓨터에서는 그 사용자의 기존 인증을 사용한다. 전역 설정·로그인을 변경하거나 인증 파일을 기기 간 복사하지 않는다.

## 연결 테스트가 확인하는 것

| 대상             | 확인 내용                                                  | 확인하지 않는 것                               |
| ---------------- | ---------------------------------------------------------- | ---------------------------------------------- |
| OpenAI API       | 저장된 키로 선택 모델 메타데이터 조회, HTTP 오류·시간 제한 | 실제 음성 정확도·생성 속도·유료 요청 가능 잔액 |
| 로컬 Whisper     | 모델 준비 상태                                             | 긴 음성의 실제 전사 속도                       |
| 개인 원격 STT    | 인증된 빈 요청에 대한 서버의 예상 응답                     | 음성 업로드·전사 품질                          |
| Codex/Claude CLI | 고정된 짧은 문장의 실제 응답                               | 장문 한국어 다듬기 품질·실사용 전체 지연       |

CLI 테스트에는 구독 사용량이 발생할 수 있다. OpenAI 연결 테스트는 음성/생성 요청을 보내지 않는다. 모바일도 모델 메타데이터만 조회하며, 저장 키·엔진이 바뀐 뒤 도착한 이전 테스트 응답은 무시한다.

## 속도 재측정과 해석

- 앞선 장애 때 같은 FP16 Whisper의 짧은 전사가 9~26초 걸렸고 초기화 시간 초과도 있었다. 원인 전체가 입증된 상태는 아니다.
- 이번 재측정에서는 **3.255초 합성 음성 → 전사 609ms**, HTTP 200, 기대 정보 보존을 확인했다. AI 다듬기는 끄고 측정했으며 FP16·모델 파일은 바꾸지 않았다.
- SB의 고정 문장 Codex 연결 검사: Sol 3,953ms, Terra 2,938ms, Luna 3,250ms. 이는 CLI 시작·응답을 포함한 연결 검사이며 한국어 전사 품질 비교가 아니다.
- 따라서 과거 서버 지연은 이번 짧은 검사에서 재현되지 않았고, CLI 대기와 전사 시간은 구분해야 한다. 한 번의 정상 결과로 간헐 장애가 영구 해결됐다고 결론 내리지 않는다. INT8 전환이나 품질 저하를 감수하는 최적화는 적용하지 않았다.
- 사용자가 모바일 API 경로의 속도·성능에 만족한다고 보고했다. 에이전트가 실제 API 음성 벤치마크를 수행한 결과와는 구분한다.

증거: 저장소 상위 `qa/key-save-20261029/legacy-current-probe.json`, `qa/models-20261029/probe-codex-models.py` 및 해당 결과 파일. 시험 음성은 합성 음성이며 개인 대화는 테스트에 사용하지 않았다.

- Windows: 프런트엔드 454개, Rust 782개 통과·5개 의도적 제외, 통합 검사 5+1+3개, release UIA helper 3개 통과. typecheck/lint/format/프로덕션 Tauri 빌드 통과. 두 Claude 실제 CLI 검사도 별도로 통과했다.
- macOS: 프런트엔드 454개, Rust 772개·통합 1개 통과·5개 의도적 제외. format/typecheck/lint/Clippy/앱 빌드·서명 검사 통과.
- Android: 로컬 120개 검사, APK 빌드·lint·서명 통과. 기기의 키 저장 UI 11개와 오프라인 통신 mock 25개 검사 통과. 실제 비밀값은 테스트에서 사용하지 않았다.
- 모바일 Google 검색창의 실제 드래그·위치 유지·취소·모드 선택은 앞선 수정에서 확인했다. [상세 원인과 실기 검증](2026-10-29-engine-cards-and-mobile-drag.md). 이번 APK에도 포함되어 있다.
- 최종 빌드의 런타임 소스 해시를 재확인했다. 기존 미커밋 변경은 보존했고 새 의존성을 설치하지 않았다.
